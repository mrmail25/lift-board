# Evolution ladder spec (ladder v2, live)

Live since 2026-10-29 (ladder v2). Supersedes ladder v1 (2026-10-25) and `data/evolution-levels-draft.md`; the swap1 and swap2 proposals in `data/proposals/` are kept as history (section 18). Machine-readable rules: `data/evolution-rules.json` (generated by `tools/build_evolution.py` from `tools/evolution_rules.py`; never hand-edit). Reference implementation: `tools/evolution.py report(history, as_of)`. Parity reference: `data/evolution-reference.json`. Tests: `tools/test_evolution.py`.

**What this is.** A strength game ladder. Every number is a modelling choice [M] anchored on crowd and coach standards; estimated 1RM is a model, not a measured max. Nothing here is a health, fitness or medical measure. Benchmarks are game thresholds anchored on crowd and coach strength standards (Strength Level, Symmetric Strength). Those sources are not peer-reviewed: Strength Level ranks self-reported lifts from its own app users; Symmetric Strength publishes model bands. Estimated 1RM is a model, not a measured max. Bodyweight scaling: allometric, exponent 0.67 (the standard size normalisation for strength). Prime = Strength Level Intermediate. Upper stages follow published powerlifting standards, checked against OpenPowerlifting raw results (public-domain dataset, data date 2026-10-24); the first three stages follow a beginner progression model.

## 1. Decisions (from Mr Dude, via Chief of Staff, Oct 25 and Oct 29)
- Strength alone earns every rank, including Prime, Kong and Apex.
- The opt-in body-composition check unlocks ONLY the "Lean Prime" art and badge. It never affects rank.
- Optional settings sex field; until set, the men's table is used with the label: "Using the men's table. Set sex in Settings to use the women's table."
- Rows and dips may stand in for one core lift the user doesn't train (max one substitution, still 3 of 5).
- Best-ever estimated 1RM (Epley, <= 12 reps, deload sessions excluded). Weighted pull-ups/dips count via a strict-rep conversion.
- Multiples use the bodyweight of the set's day; fallback = nearest earlier entry, then the profile bodyweight.
- Plate badges in lb (135/225/315/405, hidden 495) or kg (60/100/140/180, hidden 220), by the unit setting; independent of rank.
- Never demote. Kong and Apex stay hidden until reached ("Locked stage"). Overall progress = 3rd-highest of the 5 lifts.
- **Ladder v2 (Oct 29):** stage order Knuckle-Dragger, Primate, Neanderthal, Prime, Silverback, Kong, Apex (Silverback visible). Bars scale with bodyweight on an allometric curve (section 12). Prime = Strength Level Intermediate (men at 180 lb: bench 220 / squat 298 / deadlift 348 / OHP 140 / 10 pull-ups; a 225 bench at 180 lb qualifies). Silverback / Kong / Apex = USPA Classic Raw and other published bars (bench 303 / 369 / 402 at 180 lb). Knuckle-Dragger, Primate and Neanderthal follow a beginner progression model so year 1 gives a rank about every 1-3 months (section 15). v1 awards migrate by threshold (section 14).

## 2. Stages, ranks and ids
Stages: Knuckle-Dragger -> Primate -> Neanderthal -> Prime -> Silverback -> Kong (hidden until reached) -> Apex (hidden until reached).
Each stage has 3 tiers. Display labels put the rank word first: tier 1 `{stage}`, tier 2 `Chief {stage}`, tier 3 `Alpha {stage}` (e.g. Primate, Chief Primate, Alpha Primate; Chief Knuckle-Dragger; Alpha Silverback). 21 ranks.
Ids are language-neutral: `<stage_id>.<tier>` (e.g. `primate.2`), index = 3 x stage index + tier - 1 (0..20). Only labels carry names. Everyone starts at `knuckle_dragger.1`.

## 3. Values per lift
- **Core lifts:** bench press (`barbell-bench-press`), squat (`back-squat`), deadlift (`deadlift`), overhead press (`overhead-press`), pull-ups (`pull-up`). **Stand-ins:** barbell row (`barbell-row`), dips (`weighted-dip`; strict dips are logged with load 0). Aliases resolved via id-aliases.json.
- **Multiple lifts:** best-ever (max over sets) of estimated 1RM / S(bodyweight on the set's day) (scaling). Estimated 1RM = Epley load x (1 + reps/30) on working sets with 1..e1rm_max_reps (rules.json logger, 12) reps; deload sessions (session.deload === true) excluded; sets tagged with e1rm in logger.set_tags[tag].pr_exclude (myo-rep, drop set, partials) excluded; only completed sessions and done sets; aliases resolved. Load = the logged load (barbell lifts have no bodyweight part).
- **Rep lifts:** best-ever strict-rep value. A set with no added load counts its reps (any rep count). A weighted set (added load > 0, reps 1..12) converts to strict-rep equivalents [M]: E = (f x BW + added) x (1 + reps/30) is its estimated 1RM, and the strict reps that reach the same estimate at bodyweight alone are r_eq = 30 x (E / (f x BW) - 1), floored to a whole rep. f = exercises.json bodyweight_fraction (0.95), BW = bodyweight on the set's day (a weighted set without a bodyweight is not rated). Negative logged loads (assistance) are not counted. Same deload / tag exclusions (tags with reps_at_load in pr_exclude excluded for strict sets, e1rm for weighted sets). The strict-rep value is then scaled x BW / S(BW) (scaling.reps_value).
  - Example: BW 180 lb, pull-up +45 lb x 5: E = (171 + 45) x 1.1667 = 252.0; r_eq = 30 x (252.0 / 171 - 1) = 14.2 -> 14 strict-rep equivalents. A model: Epley extrapolated to high reps is rough, so converted values are approximate. Labelled "Includes weighted sets (converted to strict reps, estimated)."
- **Bodyweight:** bodyweight for a set = the latest history.bodyweights entry dated on or before the set's session local date (startedAt || date); none -> settings.profile.bodyweight; none -> the set is not rated for multiple lifts (and weighted reps sets); strict reps need no bodyweight. Unlike prs.py there is no backfill from a later entry: a later weigh-in never rewrites an older rank. Current bodyweight (targets): for next-rank targets: latest entry on or before as_of; none -> settings.profile.bodyweight; none -> targets shown as multiples only.
- A rep threshold of 0 is met by any rated value (i.e. at least one strict rep logged).

## 5. Promotion, progress, never demote
- overall rank = the highest rank index met by at least 3 of the 5 core lifts (after at most one stand-in substitution). A lift meets a rank when value >= that rank's threshold. Unlogged or unrated lifts meet nothing. Everyone starts at knuckle_dragger.1.
- **Per-lift stage:** each lift (core and stand-ins) shows its own rank: the highest rank whose threshold it meets (hidden stages beyond the revealed ladder show as "Locked stage"). A rated lift below its Knuckle-Dragger value still shows Knuckle-Dragger.
- **Never demote:** shown rank = max(computed rank, history.evolution.awarded). The app stores the highest rank shown in history.evolution.awarded {stage, tier, ladder_version: 2}; a drop, a bodyweight gain, a sex change or a deleted set never lowers it (held: true while computed < awarded).
- **Progress:** p = clamp((value - T_rank) / (T_next - T_rank), 0, 1) with T_rank / T_next = that lift's thresholds at the shown overall rank and the next rank; T_next == T_rank -> 1 if value >= T_next else 0; unlogged / unrated -> 0. 3rd-highest of the 5 slot progresses (core lifts after substitution). It reaches 1.0 exactly when a 3rd lift meets the next rank, which is the promotion rule. At the top rank (apex.3) progress is null. Display: pct = floor(100 x overall).
- **Targets:** multiple target load = T_next x S(current bodyweight), rounded UP to the unit step; reps target = ceil(T_next x S(BW) / BW) reps at the current bodyweight (T_next reps when no bodyweight). Step: lb 5, kg 2.5.
- **Hidden stages:** kong and apex stages (only these two; silverback is visible) show as "Locked stage" in the ladder, the next-rank name and per-lift stages until the overall rank (with the awarded floor) reaches them. When the shown rank first enters Kong (or Apex), `newly_revealed` lists it and the label "New stage unlocked: Kong" is returned once (the app stores `awarded` after showing it).

## 7. Plate badges (separate from rank)
Unit: settings.unit ("lb" default | "kg") picks the set; both lists exist. lb [135, 225, 315, 405, 495], kg [60, 100, 140, 180, 220]. Bench, squat, deadlift: 5 badges; overhead press: 2. earned by the first done working set (non-deload, reps >= 1, not tagged with weight in pr_exclude) whose logged load, converted to the setting unit, is >= the plate load - 0.01. A real set, not an estimate. Independent of rank.
- **Hidden five plates:** The five-plate badges (495 lb / 220 kg: five 45 lb or 20 kg plates a side on a 45 lb / 20 kg bar) on bench, squat and deadlift are hidden until earned. Only these entries carry a hidden key: hidden: true and label "Hidden badge" until a qualifying set exists, then hidden: false and the normal label, shown like the other plate badges. Plates 1-4 have no hidden key. Overhead press stays at two plates. Not a tier; independent of rank. Unearned entry: `{"id": "bench.plates5", "lift": "bench", "plates": 5, "load": 495, "unit": "lb", "label": "Hidden badge", "earned": false, "date": null, "set_id": null, "hidden": true}`; once earned: the normal label, earned true, date and set_id set, hidden false.

## 8. Lean Prime (opt-in, art and badge only)
- Opt-in physique condition that unlocks ONLY the "Lean Prime" art and badge. It never affects rank. A leanness game condition, not a health measure.
- Badge: unlocked when lean.status == pass and the shown rank is at stage prime or above; stale -> shown greyed (prime is stage 3 in ladder v2, so silverback, kong and apex also qualify).
- Opt-in: settings.bodyComp.optIn === true. Never on by default; never asked during onboarding. Hide switch: settings.bodyComp.hidden === true hides every body-composition field, status and badge (status "hidden"). Age: settings.profile.birthDate (YYYY-MM-DD) gives age at as_of; under 18 -> no body-composition features at all (status "unavailable"). Age unknown -> not offered until a birth date is entered (status "needs_age" when opted in).
- Inputs: settings.profile.height {value, unit:"cm"|"in"}; history.bodyComp [{date, waist?:{value, unit}, bfPct?, bfMethod?:"dexa"|"calipers"|"bia"|"eye"}].
- **Primary: Waist-to-height ratio** (waist at the navel, standing relaxed, after a normal breath out, divided by height (same units)): men <= 0.46, women <= 0.45.
- **Fallback: Entered body-fat %** (no waist entry (with a height) in the window): men <= 15%, women <= 23%; methods dexa, calipers, bia; eye estimates not accepted. "Body-fat readings can be off by 3-5 points."
- **Age allowance** [M] not evidence-based; a game allowance: 40-49 +0.01 WHtR / +2 points; 50+ +0.02 / +4.
- Readings: use the best (lowest) reading of the decisive method dated within the last 90 days up to as_of, so the mark does not flicker; only older readings -> stale (greyed). Sex: same as the strength table: unset -> men's thresholds, with the same label.
- Statuses: hidden, unavailable, not_tracked, needs_age, needs_entry, pass, not_yet, stale. Labels: pass = "Lean physique tracked"; not_yet = "Physique tracked"; not_tracked = "Physique not tracked"; needs_entry = "Add a waist or body-fat entry to track your physique"; needs_age = "Add your birth date to use physique tracking"; stale = "Update your waist to keep the Lean mark". hidden / unavailable show nothing.
- Copy rules: Use "lean" and "visible physique". Never "healthy", "fit" or "ideal"; no "lose X" prompts; no streaks, notifications or comparisons tied to waist or weight.
- Waist-to-height ratio as a height-adjusted waist measure: Ashwell M, Gunn P, Gibson S. Obes Rev. 2012;13(3):275-286, doi:10.1111/j.1467-789X.2011.00952.x (verified via Crossref; its subject is cardiometabolic risk, which this game does not claim to assess; cited only for where the measure comes from). The cut-offs here are game cut-offs [M]. FFMI and BMI are not used (BMI mislabels muscular lifters; FFMI measures lean mass, not leanness: Kouri EM et al., Clin J Sport Med 1995;5(4):223-228, doi:10.1097/00042752-199510000-00003, verified via Crossref).

## 12. Bodyweight scaling (allometric)
**In plain words:** your bar is the anchor lifter's bar (a 180 lb man, or a 145 lb woman) times (your bodyweight / anchor bodyweight) to the power 2/3 (exactly 0.67). Double your bodyweight and the bar rises by about 59%, not 100%: bigger lifters must lift more in total, but less per pound of bodyweight. That matches how strength scales with muscle cross-section (area grows as mass^(2/3)), the standard size-normalisation in the strength literature (Jaric S. Muscle strength testing: use of normalisation for body size. Sports Med. 2002;32(10):615-631, doi:10.2165/00007256-200232100-00002, verified via Crossref). Fair both ways: a flat 1.2222x multiple asks a 240 lb man for 293 lb at Prime and a 130 lb man for 159 lb; the curve asks 265 and 175 lb. Outside 110-320 lb (men) / 90-250 lb (women) the bar stops changing shape: Below the clamp the multiple is held (no ever-steeper multiples for very light lifters); above it the load is held, because extra mass beyond roughly the top of the open weight classes adds little strength, so a heavier lifter is never asked for more load.
- **Formula:** S(BW) in kg, with a = the anchor bodyweight and [lo, hi] the clamp: lo <= BW <= hi -> S = a x (BW / a)^0.67; BW < lo -> S = BW x (lo / a)^(0.67 - 1) (the multiple at lo is held); BW > hi -> S = a x (hi / a)^0.67 (the load at hi is held). S(a) = a and S is continuous.
- **Values:** value of a barbell lift = estimated 1RM (kg) / S(bodyweight of the set's day): the "anchor-equivalent multiple". At the anchor bodyweight it equals the plain multiple. Thresholds stay as anchor multiples, so threshold load at bodyweight BW = threshold x S(BW). value of a rep lift = strict reps (weighted sets converted to strict-rep equivalents at the lifter's own bodyweight, as before) x BW / S(BW), rounded to 4 dp. At the anchor bodyweight it equals the logged reps; heavier lifters get modestly more credit per rep (x1.10 at 240 lb), lighter lifters modestly less (x0.92 at 140 lb). A strict set with no bodyweight on file counts its plain reps (unscaled).
- **Targets:** multiple target load = T_next x S(current bodyweight), rounded UP to the unit step; reps target = ceil(T_next x S(BW) / BW) reps at the current bodyweight (T_next reps when no bodyweight).
- **Why this curve:** Strength grows with body size, but less than in proportion: a flat multiple of bodyweight favours light lifters and penalises heavy ones. Allometric scaling with an exponent near 2/3 (force ~ muscle cross-section ~ mass^(2/3)) is the classic, published correction (Sports Med 2002 review on normalising strength for body size). Chosen over DOTS because it is one line of JS with one constant per sex, is the same shape for every lift and sex, and needs no fitted polynomial; over a lift-specific exponent fitted to OpenPowerlifting because competitor data across weight classes mixes body size with selection (fitted log-log exponents: men bench 0.68, squat 0.65, deadlift 0.48; women 0.45 / 0.46 / 0.36), which would make the deadlift and the women's table almost flat-load and over-reward heavy lifters. DOTS (a fitted 4th-degree polynomial in bodyweight, published by the IPF-affiliated coefficient set used by OpenPowerlifting) was considered and not used: it needs a polynomial per sex and was fitted to totals, not single lifts.
- **Clamp:** men 110-320 lb, women 90-250 lb. Inside the clamp (men 110-320 lb, women 90-250 lb) the curve behaves sensibly (men: multiple x1.18 at 110 lb, x0.83 at 320 lb vs 180 lb). Below the clamp the multiple is held (no ever-steeper multiples for very light lifters); above it the load is held, because extra mass beyond roughly the top of the open weight classes adds little strength, so a heavier lifter is never asked for more load.
- **Pull-ups and dips:** Pull-ups and dips lift the body, so heavier lifters do fewer reps at the same relative strength (Strength Level pull-up standards, men Intermediate: 14 reps at 140 lb, 13 at 180 lb, 11 at 240 lb). The same S(BW) factor gives a modest adjustment in that direction (13 at 180 lb ~ 14.1 at 140 lb, 11.8 at 240 lb); an Epley-based rep conversion was rejected because it exaggerates the drop at high reps (about 30% fewer reps at 240 lb). Weighted sets convert to strict reps first (section 3), then scale the same way; the row stand-in scales like every barbell lift.
- **Citations (author names in this document only, not in app data or labels):** Jaric S. Muscle strength testing: use of normalisation for body size. Sports Med. 2002;32(10):615-631. doi:10.2165/00007256-200232100-00002. Vanderburgh PM, Batterham AM. Validation of the Wilks powerlifting formula. Med Sci Sports Exerc. 1999;31(12):1869. doi:10.1097/00005768-199912000-00027. Both verified via Crossref 2026-10-29; the second is background on allometric modelling of powerlifting performance.
- **Lifters carrying a lot of body fat.** Compared with flat multiples, the curve HELPS a heavier lifter: at 240 lb the Prime bench bar is 265 lb (1.11x) instead of 293 lb (1.2222x), and the 320 lb clamp stops the bar rising for anyone heavier. It does not reward fat gain itself: if the same person goes from 200 to 240 lb of mostly fat with no strength change, the bar rises by 13% (flat multiples: 20%), so his rating still drops, by less than before. Strength alone earns rank; the opt-in Lean Prime badge (unchanged, needs Prime or above) is the only physique element and never affects rank.

## 14. Migration of v1 awards (history.evolution.awarded)
- **Ids:** language-neutral "<stage_id>.<tier>" (e.g. "primate.2"); index = 3 x stage index + tier - 1 (0..20). Only display labels carry names. Stage ids are unchanged from ladder v1; only prime and silverback swap positions (prime: stage 4 -> 3, silverback: 3 -> 4), so their rank indexes change (prime.N 12-14 -> 9-11, silverback.N 9-11 -> 12-14).
- **Detect:** history.evolution.awarded without ladder_version (or ladder_version 1) is a v1 award. Accepted v1 forms: {stage, tier} (stage id + tier, the documented form), {index} or a bare integer (a v1 rank index 0..20).
- **Rule:** Map by threshold, never by id: take the v1 rank (old stage order, old flat tables for the user's current sex table) and use as the floor the HIGHEST v2 rank whose bars on all 5 core lifts are each <= the v1 rank's bars x k x (1 + tolerance): new threshold <= old threshold x k x 1.03, with k = BW / S(BW) at the current bodyweight (as_of; k = 1 with no bodyweight) and tolerance = 0.03. The 3% tolerance absorbs small differences between the v1 bars and the published bars of v2 (e.g. a woman's v1 Prime bench 0.75x vs the v2 0.7655x), so an award is not dropped a rank for a gap of a few pounds; a v2 bar more than 3% above the v1 bar still floors lower. It applies ONLY to migrating a stored v1 award; computed ranks never use it. Then shown = max(computed v2 rank, floor); awarded_out is written back with ladder_version 2 and never lowered again.
- **Why not by id:** ids are stable but silverback moved above prime: copying "silverback.2" across would promote a v1 Chief Silverback (bench 1.08x) past Prime (1.25x). Copying the index would rename ranks arbitrarily.
- **Labels:** The floor can carry a different name than the v1 award: a v1 Prime stays Prime (men at 180 lb: v1 bars 225 / 315 / 360 / 144 / 10 >= the v2 220 / 298 / 348 / 140 / 10; women at 145 lb: within the 3% tolerance, v1 bench 108.75 vs v2 111), a v1 Silverback reads as a Neanderthal rank (v1 Silverback sat below Prime), and a v1 Kong or Apex as a Prime or Silverback rank (the v2 Kong and Apex bars are much higher); Kong hides again until reached under the v2 bars. The computed rank from the user's logged lifts usually lands higher; nothing the user lifted is lost.
- **Output:** report().awarded_migration = {from: v1 id, from_index, to: v2 id, to_index} when a v1 award was read, else null. migration.table is computed at the anchor bodyweight (k = 1) with the 3% tolerance; the app computes the floor at the lifter's current bodyweight.
- **Tolerance:** `migration.tolerance` = 0.03 (each v2 bar may be up to 3% above the v1 bar after k). Migration only; computed ranks never use it.
- **Examples at 180 lb (men):** v1 Prime `prime.1` -> `prime.1` (a v1 Prime stays Prime); v1 Chief Prime `prime.2` -> `prime.1` (v2 Chief Prime bars are 3.2-3.4% above v1, just outside the tolerance); v1 Chief Silverback `silverback.2` -> `neanderthal.3`; v1 Kong `kong.1` -> `prime.3`; v1 Apex `apex.1` -> `prime.3`. **At 145 lb (women):** v1 Prime `prime.1` -> `prime.1` (v2 bench 2.1% above v1, inside the tolerance).

## 15. Effort check (progression model, estimates)

Constant bodyweight, each lift trained 1-2x a week. Start multiples = a first-month beginner (men bench 0.40, squat 0.50, deadlift 0.60, OHP 0.25; women = the men's start x the women/men Prime ratio, so both reach Prime at the same model age). Lower stages: Knuckle-Dragger entry = the model value 4 weeks before the start (about 0.9 x start), Primate = week 24, Neanderthal = week 48, rounded to 5 lb (men, 180 lb) / 2.5 lb (women, 145 lb). Stage years = the 3rd-fastest of the four barbell lifts (3 of 5 lifts promote; pull-ups assumed to keep pace). A smooth curve chosen to resemble typical progress: an estimate, not a study result; real progress varies widely. Years are in anchor-equivalent terms (the curve takes bodyweight changes into account).

### Lean-mass gain sanity check (rule-of-thumb models, NOT peer-reviewed)
- **McDonald model** (coach rule of thumb, men): about 20-25 lb of lean mass in year 1 of proper training, 10-12 lb in year 2, 5-6 lb in year 3, then 2-3 lb a year; women about half.
- **Aragon model** (coach rule of thumb): about 1-1.5% of bodyweight a month for beginners, 0.5-1% for intermediates, 0.25-0.5% for advanced lifters.
- Both are non-peer-reviewed rules of thumb (no peer-reviewed numbers are used here) and individual results vary widely. Model names appear only in this spec note, never in app data or labels.
- **Journey check:** the ladder puts Prime at ~3.3 years and Silverback / Kong / Apex at ~9.7 / ~12.6 / ~17.8 years. By the McDonald model a man at 180 lb at Prime (year ~3) adds about 2-3 lb of lean mass a year, so +10 lb by Silverback (year ~10) and +20 lb by Kong (year ~13) is plausible as mostly lean gain (2-3 lb a year over 6-9 years, plus some fat). If he gains faster than that, the extra is mostly fat, and the curve raises his bars by about 2/3 of the bodyweight change.

## 16. Plate badges: hidden five plates
- Plates: lb [135, 225, 315, 405, 495], kg [60, 100, 140, 180, 220]; bench, squat, deadlift up to five plates, overhead press two.
- The five-plate badges (495 lb / 220 kg: five 45 lb or 20 kg plates a side on a 45 lb / 20 kg bar) on bench, squat and deadlift are hidden until earned. Only these entries carry a hidden key: hidden: true and label "Hidden badge" until a qualifying set exists, then hidden: false and the normal label, shown like the other plate badges. Plates 1-4 have no hidden key. Overhead press stays at two plates. Not a tier; independent of rank.
- **Decision:** Five plates on all three barbell lifts, all hidden until earned: one simple rule for the top plate. A 495 lb bench is the rare one (above the Apex bench at 180 lb); for a 180 lb man a 495 squat comes between Silverback (474) and Kong (529) and a 495 deadlift just before Silverback (513), so they act as a surprise along the way rather than an end-game marker.

## 17. Builder handoff (ladder v1 -> v2)
- **Stage order:** Knuckle-Dragger -> Primate -> Neanderthal -> Prime -> Silverback -> Kong -> Apex. Stage ids and rank ids are unchanged (`<stage_id>.<tier>`); only `prime` and `silverback` swap positions: Prime is stage 3 (rank indexes 9-11, was 12-14), Silverback stage 4 (indexes 12-14, was 9-11). Only Kong and Apex hide ("Locked stage"); Silverback is visible. Lean Prime still needs stage `prime` or above.
- **Rules fields:** `ladder_version` 2, `scaling` (anchor bodyweights, exponent 0.67, clamps, S(BW)), `tables.<sex>.<lift>` (stage_entries are anchor-equivalent multiples; use `ranks` as given), `migration` (old_stage_order, old_tables, detect, rule, table), `plate_badges` (unchanged from the hidden five-plate release), plus documentation blocks `standards`, `alignment`, `opl`, `progression_model`, `years_to_reach`, `rank_months`, `changelog` (no app logic).
- **Values:** a barbell value = estimated 1RM / S(bodyweight of the set's day); a rep value = strict reps x BW / S(BW). Report adds `lifts.<lift>.unscaled` (the plain multiple, for display), `labels.scaled` (the one-line "Bars adjust for bodyweight" note from `labels.scaled_note`) and, when a stored award is migrated, `awarded_migration` {from, from_index, to, to_index}; `awarded_out` carries `ladder_version: 2`.
- **Migration:** an award without `ladder_version` (or 1) is a v1 award ({stage, tier}, {index} or a bare int); floor = the highest v2 rank whose 5 core bars are all <= the v1 rank's bars x k x (1 + `migration.tolerance`), k = BW / S(BW), tolerance 0.03 (migration only; never used for computed ranks); shown = max(computed, floor); write back `awarded_out`.
- **Parity:** diff `REF.sample.expected` and each `REF.edge_cases[k].expected` (37 cases, was 25 on v1).
