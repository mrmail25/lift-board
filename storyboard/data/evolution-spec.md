# Evolution ladder spec (evolution1, final)

Supersedes `data/evolution-levels-draft.md` (v2 draft, kept for history). Machine-readable rules: `data/evolution-rules.json` (generated by `tools/build_evolution.py` from `tools/evolution_rules.py`; never hand-edit). Reference implementation: `tools/evolution.py report(history, as_of)`. Parity reference: `data/evolution-reference.json`. Tests: `tools/test_evolution.py`.

**What this is.** A strength game ladder. Every number is a modelling choice [M] anchored on crowd and coach standards; estimated 1RM is a model, not a measured max. Nothing here is a health, fitness or medical measure. Benchmarks are game thresholds anchored on crowd and coach strength standards (Strength Level, Symmetric Strength). Those sources are not peer-reviewed: Strength Level ranks self-reported lifts from its own app users; Symmetric Strength publishes model bands. Estimated 1RM is a model, not a measured max.

## 1. Decisions (from Mr Dude, via Chief of Staff, Oct 25)
- Strength alone earns every rank, including Prime, Kong and Apex.
- The opt-in body-composition check unlocks ONLY the "Lean Prime" art and badge. It never affects rank.
- Optional settings sex field; until set, the men's table is used with the label: "Using the men's table. Set sex in Settings to use the women's table."
- Rows and dips may stand in for one core lift the user doesn't train (max one substitution, still 3 of 5).
- Best-ever estimated 1RM (Epley, <= 12 reps, deload sessions excluded). Weighted pull-ups/dips count via a strict-rep conversion.
- Multiples use the bodyweight of the set's day; fallback = nearest earlier entry, then the profile bodyweight.
- Plate badges in lb (135/225/315/405) or kg (60/100/140/180), by the unit setting.
- Never demote. Kong and Apex stay hidden until reached. Overall progress = 3rd-highest of the 5 lifts.

## 2. Stages, ranks and ids
Stages: Knuckle-Dragger -> Primate -> Neanderthal -> Silverback -> Prime -> Kong (hidden until reached) -> Apex (hidden until reached).
Each stage has 3 tiers. Display labels put the rank word first: tier 1 `{stage}`, tier 2 `Chief {stage}`, tier 3 `Alpha {stage}` (e.g. Primate, Chief Primate, Alpha Primate; Chief Knuckle-Dragger; Alpha Silverback). 21 ranks.
Ids are language-neutral: `<stage_id>.<tier>` (e.g. `primate.2`), index = 3 x stage index + tier - 1 (0..20). Only labels carry names. Everyone starts at `knuckle_dragger.1`.

## 3. Values per lift
- **Core lifts:** bench press (`barbell-bench-press`), squat (`back-squat`), deadlift (`deadlift`), overhead press (`overhead-press`), pull-ups (`pull-up`). **Stand-ins:** barbell row (`barbell-row`), dips (`weighted-dip`; strict dips are logged with load 0). Aliases resolved via id-aliases.json.
- **Multiple lifts:** best-ever (max over sets) of estimated 1RM / bodyweight on the set's day. Estimated 1RM = Epley load x (1 + reps/30) on working sets with 1..e1rm_max_reps (rules.json logger, 12) reps; deload sessions (session.deload === true) excluded; sets tagged with e1rm in logger.set_tags[tag].pr_exclude (myo-rep, drop set, partials) excluded; only completed sessions and done sets; aliases resolved. Load = the logged load (barbell lifts have no bodyweight part).
- **Rep lifts:** best-ever strict-rep value. A set with no added load counts its reps (any rep count). A weighted set (added load > 0, reps 1..12) converts to strict-rep equivalents [M]: E = (f x BW + added) x (1 + reps/30) is its estimated 1RM, and the strict reps that reach the same estimate at bodyweight alone are r_eq = 30 x (E / (f x BW) - 1), floored to a whole rep. f = exercises.json bodyweight_fraction (0.95), BW = bodyweight on the set's day (a weighted set without a bodyweight is not rated). Negative logged loads (assistance) are not counted. Same deload / tag exclusions (tags with reps_at_load in pr_exclude excluded for strict sets, e1rm for weighted sets).
  - Example: BW 180 lb, pull-up +45 lb x 5: E = (171 + 45) x 1.1667 = 252.0; r_eq = 30 x (252.0 / 171 - 1) = 14.2 -> 14 strict-rep equivalents. A model: Epley extrapolated to high reps is rough, so converted values are approximate. Labelled "Includes weighted sets (converted to strict reps, estimated)."
- **Bodyweight:** bodyweight for a set = the latest history.bodyweights entry dated on or before the set's session local date (startedAt || date); none -> settings.profile.bodyweight; none -> the set is not rated for multiple lifts (and weighted reps sets); strict reps need no bodyweight. Unlike prs.py there is no backfill from a later entry: a later weigh-in never rewrites an older rank. Current bodyweight (targets): for next-rank targets: latest entry on or before as_of; none -> settings.profile.bodyweight; none -> targets shown as multiples only.
- A rep threshold of 0 is met by any rated value (i.e. at least one strict rep logged).

## 4. Tables (stage entries; x bodyweight, reps for pull-ups/dips)
Rank thresholds: tier 1 = stage entry; tier 2 (Chief) = entry + 1/3 x (next stage entry - entry); tier 3 (Alpha) = entry + 2/3 x gap; the Apex gap runs to the ceiling. Multiples rounded to 4 dp, reps rounded half up. The 21 values per lift are listed in tables.<sex>.<lift>.ranks and are authoritative.

## 5. Promotion, progress, never demote
- overall rank = the highest rank index met by at least 3 of the 5 core lifts (after at most one stand-in substitution). A lift meets a rank when value >= that rank's threshold. Unlogged or unrated lifts meet nothing. Everyone starts at knuckle_dragger.1.
- **Per-lift stage:** each lift (core and stand-ins) shows its own rank: the highest rank whose threshold it meets (hidden stages beyond the revealed ladder show as "???"). A rated lift below its Knuckle-Dragger value still shows Knuckle-Dragger.
- **Never demote:** shown rank = max(computed rank, history.evolution.awarded). The app stores the highest rank shown in history.evolution.awarded {stage, tier}; a drop, a bodyweight gain, a sex change or a deleted set never lowers it (held: true while computed < awarded).
- **Progress:** p = clamp((value - T_rank) / (T_next - T_rank), 0, 1) with T_rank / T_next = that lift's thresholds at the shown overall rank and the next rank; T_next == T_rank -> 1 if value >= T_next else 0; unlogged / unrated -> 0. 3rd-highest of the 5 slot progresses (core lifts after substitution). It reaches 1.0 exactly when a 3rd lift meets the next rank, which is the promotion rule. At the top rank (apex.3) progress is null. Display: pct = floor(100 x overall).
- **Targets:** for each slot below the next rank: multiple target = T_next x current bodyweight as an estimated 1RM, rounded UP to the unit step; reps target = T_next reps. Step: lb 5, kg 2.5.
- **Hidden stages:** kong and apex stages show as "???" in the ladder, the next-rank name and per-lift stages until the overall rank (with the awarded floor) reaches them. When the shown rank first enters Kong (or Apex), `newly_revealed` lists it and the label "New stage unlocked: Kong" is returned once (the app stores `awarded` after showing it).

## 6. Substitution (max 1)
| Stand-in | For | Scale | Tables | Source |
|---|---|---|---|---|
| Barbell row | Pull-ups | barbell row multiples (tables.<sex>.row) | men, women | Strength Level bent-over row ratios (men and women), interpolated [M] |
| Dips | Bench press | strict dip reps (tables.<sex>.dips) | men, women | Strength Level dips rep standards (men: Beginner 4 / Novice 10 / Intermediate 20 / Advanced 31 / Elite 42 at 180 lb; women: <1 / 1 / 9 / 18 / 29 community-wide), interpolated [M]; men's scale set slightly below Strength Level, like pull-ups |

Rule: only when a core lift is not trained (no qualifying working set ever, deload excluded) and its stand-in has a rated value. At most one substitution; if two are possible, take the one giving the higher overall rank, then higher overall progress, then the order above. A trained-but-unrated core lift (e.g. no bodyweight) is not substituted. Label: "{stand_in} stands in for {lift}".

## 7. Plate badges (separate from rank)
Unit: settings.unit ("lb" default | "kg") picks the set; both lists exist. lb [135, 225, 315, 405], kg [60, 100, 140, 180]. Bench, squat, deadlift: 4 badges; overhead press: 2. earned by the first done working set (non-deload, reps >= 1, not tagged with weight in pr_exclude) whose logged load, converted to the setting unit, is >= the plate load - 0.01. A real set, not an estimate. Independent of rank.

## 8. Lean Prime (opt-in, art and badge only)
- Opt-in physique condition that unlocks ONLY the "Lean Prime" art and badge. It never affects rank. A leanness game condition, not a health measure.
- Badge: unlocked when lean.status == pass and the shown rank is at stage prime or above; stale -> shown greyed.
- Opt-in: settings.bodyComp.optIn === true. Never on by default; never asked during onboarding. Hide switch: settings.bodyComp.hidden === true hides every body-composition field, status and badge (status "hidden"). Age: settings.profile.birthDate (YYYY-MM-DD) gives age at as_of; under 18 -> no body-composition features at all (status "unavailable"). Age unknown -> not offered until a birth date is entered (status "needs_age" when opted in).
- Inputs: settings.profile.height {value, unit:"cm"|"in"}; history.bodyComp [{date, waist?:{value, unit}, bfPct?, bfMethod?:"dexa"|"calipers"|"bia"|"eye"}].
- **Primary: Waist-to-height ratio** (waist at the navel, standing relaxed, after a normal breath out, divided by height (same units)): men <= 0.46, women <= 0.45.
- **Fallback: Entered body-fat %** (no waist entry (with a height) in the window): men <= 15%, women <= 23%; methods dexa, calipers, bia; eye estimates not accepted. "Body-fat readings can be off by 3-5 points."
- **Age allowance** [M] not evidence-based; a game allowance: 40-49 +0.01 WHtR / +2 points; 50+ +0.02 / +4.
- Readings: use the best (lowest) reading of the decisive method dated within the last 90 days up to as_of, so the mark does not flicker; only older readings -> stale (greyed). Sex: same as the strength table: unset -> men's thresholds, with the same label.
- Statuses: hidden, unavailable, not_tracked, needs_age, needs_entry, pass, not_yet, stale. Labels: pass = "Lean physique tracked"; not_yet = "Physique tracked"; not_tracked = "Physique not tracked"; needs_entry = "Add a waist or body-fat entry to track your physique"; needs_age = "Add your birth date to use physique tracking"; stale = "Update your waist to keep the Lean mark". hidden / unavailable show nothing.
- Copy rules: Use "lean" and "visible physique". Never "healthy", "fit" or "ideal"; no "lose X" prompts; no streaks, notifications or comparisons tied to waist or weight.
- Waist-to-height ratio as a height-adjusted waist measure: Ashwell M, Gunn P, Gibson S. Obes Rev. 2012;13(3):275-286, doi:10.1111/j.1467-789X.2011.00952.x (verified via Crossref; its subject is cardiometabolic risk, which this game does not claim to assess; cited only for where the measure comes from). The cut-offs here are game cut-offs [M]. FFMI and BMI are not used (BMI mislabels muscular lifters; FFMI measures lean mass, not leanness: Kouri EM et al., Clin J Sport Med 1995;5(4):223-228, doi:10.1097/00042752-199510000-00003, verified via Crossref).

- **Ladder hide-all switch:** `settings.ladder.hidden` (boolean, optional (missing = false)). settings.ladder.hidden === true hides the whole ladder UI (rank chip, ladder, progress bar, next-rank targets, plate badges, Lean Prime). Display flag only: report() output is identical either way, ranks keep being computed, history.evolution.awarded keeps updating, and nothing is ever demoted or reset. Turning it off shows the current rank. Separate from bodyComp: settings.bodyComp.hidden (hides only body-composition fields, status and the Lean Prime badge). The two flags are independent; either can be on. Label when hidden (settings only): "Ladder hidden. Your rank is still tracked and is never lowered.". Chosen by Builder (788fb43).
