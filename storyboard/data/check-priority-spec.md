# Program check priority (round 3, 2026-10-23)

Generated by tools/build_round3.py. Reference: tools/check_priority.py. Weights: data/check-priority-weights.json (a `check_priority` key, merge into rules.json as-is). Fixture: data/check-priority-reference.json. Every weight is a design choice, not evidence; scores are a model, not a measurement.

## Rule

Card order (CoS call, 2026-10-23): **state first** (red, then amber), then `score = severity x importance x fixability` within a state. Info items never appear on the program-check card (they stay in the full analysis). No minimum score: every red / amber issue is eligible; an issue with no validated fix still shows, with `action: see_analysis` (no Apply / Undo ops). Cap 3. A board with no red / amber issue shows none.

### Severity

severity = lo + (hi - lo) * d, where [lo, hi] = state_band[state] and d in [0, 1] is the distance from range (see distance). red = a failing check (non-info flag); amber = close to target (weekly_band, stretch share below 0.25); info = an info note.

| State | Band |
|---|---|
| red | 0.7-1.0 |
| amber | 0.4-0.6 |
| info | 0.1-0.3 |

Distance d (0-1) from range:

- weekly_volume / weekly_band under: `min(1, (level_min - sets) / level_min)`
- weekly_volume / weekly_band over: `min(1, (sets - max) / max)`
- stretch_share: `min(1, (0.25 - share) / 0.25)`
- missing_stretch: `1`
- low_frequency / effective_frequency: `(2 - days) / 2`
- session_length: `info: (min - 75) / 15; warn: min(1, (min - 90) / 30)`
- session_hard_sets: `info: (sets - (cap - info_band)) / info_band; warn: min(1, (sets - cap) / cap)`
- junk_volume_session / redundant_pattern: `min(1, (sets - 10) / 10)`
- pattern_gap: `(min - count) / min`
- push_pull_imbalance: `min(1, distance of the ratio outside 0.75-2.0 / 0.75)`
- recovery_vs_baseline: `min(1, (ratio - 1.15) / 0.35)`
- other: `1`

Rationale (design choice): Big prime movers that carry most of a physique and most weekly sets (chest, back, quads, glutes, hamstrings) = 1.0. Delts and arms, which the app targets directly and users notice, 0.75-0.85; front delts 0.6 because pressing already covers them. Calves 0.7. Muscles that mostly get indirect work or small targets (traps, abs, adductors, obliques, abductors, lower back, forearms) 0.4-0.6. A design choice for ordering the card, not evidence about which muscles matter more. The app has no neck muscle.
Board-level issues (session length, push:pull, spine sets, pattern gaps) use muscle weight 1.0.

Excluded: `lower_fatigue_swap`: An optimisation, not a check: it never appears on the program-check card (it stays in the Recovery & fatigue suggestions).

### Fixability

| Rule | Value | When |
|---|---|---|
| single_op | 1.0 | a validated fix resolves the issue with one op (sets, swap, add or move one tile) |
| two_ops | 0.8 | a validated fix resolves it with two ops |
| restructure | 0.6 | a validated fix resolves it with three or more ops |
| partial | 0.4 | only partial fixes (move toward the goal without meeting it) |
| none | 0.2 | no validated fix: needs restructuring by hand |

Fixes come from analysis.py sheet(): every fix is validated (it never adds a non-info flag, so it stays within session limits). The best fix (resolving first, then fewest ops) becomes the issue's Apply action.

### Dedupe, sort order, cap

One issue per (family, muscle or day): weekly_volume + weekly_band, low_frequency + effective_frequency, missing_stretch + stretch_share collapse to the highest score.

Sort order: state: red, then amber > score (rounded to 4 decimals) desc > distance d desc > muscle weight desc > issue id asc. Card states: red, amber. Cap 3.

Builder fields to mirror: `sort_order`, `card_states`, `exclude_kinds` (states [info] + excluded sources), `no_fix_action` (see_analysis, fix null), `cap`; `min_score` is null (not used).

## Issue fields

| Field | Meaning |
|---|---|
| id | `<family>:<muscle or day or slot>` |
| family, source | check family (weights) and the sheet source / rule id |
| analysis_item | a real rules.json analysis_metrics item id (weights `analysis_item.rule`): missing_stretch -> stretch_<m> for checked muscles, else stretch_coverage; stretch_share -> stretch_share; session_hard_sets -> session_design; session_length -> session_length; others -> check_weight[family].item |
| analysis_item_muscle | the muscle row to highlight inside analysis_item (= muscle; null for board-level issues) |
| state | red (failing check) or amber (close to target); info issues exist in issues() but never reach the card |
| muscle, days, exercises | what it is about and what causes it |
| target | the sheet target (muscle, sets, share, flag) |
| distance, severity | d and the banded severity |
| importance | {check_weight, muscle_weight, value} |
| fixability | {rule, value} |
| score | product, 4 decimals |
| action | apply (fix set) or see_analysis (no validated fix: link to analysis_item, no Apply / Undo) |
| fix | {ops (analysis.py apply_ops diff: swap / add / sets / remove), preview, resolves, undo (inverse ops)} or null |

## Compared with the Builder's interim order

Interim order: fails (red) before close-to-target (amber), then biggest gap. Ours now uses the same state order and the same card states (info left out of both), so red always comes before amber and the two can only differ inside a state, where ours orders by score (severity x importance x fixability) and the interim order by gap alone:

- a small-muscle or low-weight issue has a bigger gap than a big-muscle one (ours ranks chest / quads over forearms / abductors at similar gaps);
- an issue has no validated fix (see_analysis, fixability 0.2) or only a partial one: ours puts it after same-state issues that Apply can fix; the interim order keeps it by gap;
- different check families at similar gaps (e.g. a pattern gap vs a stretch share): the check weight decides in ours.

Both show nothing when a board has no red / amber issue, and neither drops a red / amber issue for a low score.
